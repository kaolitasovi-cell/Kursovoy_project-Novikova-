## Введение

Квадрокоптер — динамически неустойчивая система. Если выключить полётный контроллер, аппарат опрокинется за доли секунды. Причина — положительная обратная связь: возникший крен увеличивает горизонтальную составляющую тяги, что ещё сильнее наклоняет дрон [3, стр. 42]. Пилот-человек не способен реагировать с частотой 250 Гц (каждые 4 мс) — это под силу только микроконтроллеру.

В проекте стабилизация реализована ПИД-регулятором. Это алгоритм, который объединяет три подхода к коррекции ошибки: пропорциональный (реакция на текущее отклонение), интегральный (устранение накопленной ошибки) и дифференциальный (демпфирование колебаний) [8, стр. 13].

**Цель курсовой работы** — детально разобрать реализацию ПИД-регулятора в учебном проекте полётного контроллера (вариант 4). Выполнены расчёты коэффициентов, мёртвой зоны, численного ПИД, Anti-Windup, микшера моторов и компенсации напряжения батареи. Все расчёты основаны на исходном коде проекта и формулах из методических указаний [8, стр. 47-51].

## 1 Теоретические основы ПИД-регулирования в БПЛА

### 1.1 Почему квадрокоптер не может летать без регулятора

Квадрокоптер неустойчив по своей природе. Собственный период колебаний даже небольшого дрона составляет менее 0,5 секунды [3, стр. 42]. Без внешнего управления малейшее возмущение (порыв ветра, неравномерность тяги) приводит к неконтролируемому вращению и падению. В проекте частота главного цикла — 250 Гц, то есть каждые 4 мс контроллер пересчитывает команды. Этого достаточно, чтобы успевать опрашивать датчики (MPU-6050 выдает данные до 1000 Гц) и вычислять выход [1, стр. 12]. Для человека даже 50 Гц — предел. Следовательно, микроконтроллер — необходимость. Частота 250 Гц выбрана как компромисс между скоростью реакции и вычислительной нагрузкой: более высокая частота потребовала бы больше ресурсов процессора, а более низкая — не успевала бы гасить возмущения [8, стр. 21].

### 1.2 Что такое ПИД-регулятор и как он устроен

ПИД расшифровывается как пропорционально-интегрально-дифференциальный регулятор. Он вычисляет сигнал управления как сумму трёх частей [8, стр. 13]:

$$u(t)=K_п\,e(t)+K_и\int_{0}^{t} e(\tau)d\tau+K_д\frac{de(t)}{dt}$$

Пропорциональная часть (P) реагирует на текущее отклонение: чем больше ошибка, тем сильнее воздействие. Интегральная (I) накапливает ошибку со временем, устраняя статическое смещение — например, при полёте в боковом ветре. Дифференциальная (D) реагирует на скорость изменения ошибки, демпфирует колебания [4, стр. 56].

В дискретном виде, для периода опроса Δt = 4 мс, уравнение принимает вид [8, стр. 15]:

$$
u[k]=K_п\,e[k]+I_{mem}[k]+K_д\,(e[k]-e[k-1])
$$
$$
I_{mem}[k]=I_{mem}[k-1]+K_и\,e[k]
$$

Именно эти формулы реализованы в коде проекта.

### 1.3 Мёртвая зона и Anti-Windup

**Мёртвая зона** — диапазон входного сигнала, в котором уставка обнуляется. В коде для центрального положения стика 1500 мкс зона составляет 1492…1508 мкс. Это предотвращает самопроизвольное вращение дрона из-за неточного возврата стика в центр. Реальные RC-передатчики имеют погрешность ±5…10 мкс, без мёртвой зоны дрон бы постоянно дрейфовал [4, стр. 18].

**Anti-Windup** — ограничение интегральной суммы. Без него при длительной большой ошибке (дрон лежит на боку) интеграл накапливается, а после исправления ошибки вызывает резкое перерегулирование. В коде интеграл ограничивается значением `pid_max_roll = 400` [8, стр. 46].

### 1.4 Микшер моторов и компенсация батареи

Выходы ПИД (roll, pitch, yaw) и общий газ преобразуются в команды для четырёх моторов. В проекте используется стандартная схема «X» (подробнее в разделе 2.5). Компенсация напряжения батареи увеличивает сигналы на моторах при разряде, так как тяга падает пропорционально квадрату напряжения: $F \sim U^2$. При падении напряжения с 12,6 В до 10,5 В тяга падает на 30,56% [8, стр. 51].

## 2 Расчётная часть (вариант 4)

### 2.1 Коэффициенты ПИД (задание 4.1)

В файле `Flight_Controller.ino` объявлены глобальные переменные:
```cpp
//PID
float pid_p_gain_roll = 2.0;    // Kp = 2.0
float pid_i_gain_roll = 0.04;   // Ki = 0.04
float pid_d_gain_roll = 20.0;   // Kd = 20.0
int pid_max_roll = 400;         // ограничение выхода и интеграла

float pid_p_gain_pitch = pid_p_gain_roll;   // Kp = 2.0
float pid_i_gain_pitch = pid_i_gain_roll;   // Ki = 0.04
float pid_d_gain_pitch = pid_d_gain_roll;   // Kd = 20.0
int pid_max_pitch = 400;

float pid_p_gain_yaw = 4.0;      // Kp = 4.0
float pid_i_gain_yaw = 0.02;     // Ki = 0.02
float pid_d_gain_yaw = 0.0;      // Kd = 0 (отключена)
int pid_max_yaw = 400;
```

**Таблица коэффициентов ПИД**

| Канал | Kp | Ki | Kd | Imax |
|-------|----|----|----|------|
| Roll (крен) | 2.0 | 0.04 | 20.0 | 400 |
| Pitch (тангаж) | 2.0 | 0.04 | 20.0 | 400 |
| Yaw (рыскание) | 4.0 | 0.02 | 0.0 | 400 |

**Почему Kp и Ki для Roll и Pitch одинаковы?**

Квадрокоптер имеет симметричную конструкцию относительно продольной и поперечной осей. Моменты инерции и аэродинамические свойства при наклонах вперёд/назад и влево/вправо практически одинаковы. Использование одинаковых коэффициентов упрощает настройку регулятора.

**Почему Kd = 0 для Yaw и как это влияет на динамику?**

Рыскание управляется разностью крутящих моментов винтов, процесс довольно инерционный. При Kd = 0 после резкого поворота дрон может немного «покачаться» по рысканию, но из-за инерции винтов эти колебания быстро затухают. Если поставить Kd > 0, он будет усиливать шум гироскопа, вызывая дрожь. Поэтому в проекте Kd = 0 — потеря демпфирования некритична.

**Чему равно pid_max_roll и почему именно 400?**

Сигнал управления моторами (PWM) лежит в диапазоне от 1000 до 2000 мкс, полный размах — 1000 единиц. Значение 400 выбрано как компромисс: оно оставляет запас для сложения выходов всех регуляторов (крен + тангаж + рыскание + газ), чтобы итоговая команда для каждого мотора не выходила за допустимые пределы (обычно 1100…2000 мкс). Величина 400 является эмпирической и широко используется.

### 2.2 Мёртвая зона (задание 4.2)

**4.2.a** channel_1 — сигнал с первого канала радиоприёмника, отвечает за крен. Значения: 1000 мкс — минимум (стик влево), 1500 мкс — центр, 2000 мкс — максимум (стик вправо). pid_roll_setpoint — уставка угловой скорости крена в °/с.

График зависимости — кусочно-линейная фигура, похожая на наклонную букву «Z» без центрального участка:

- левый участок (X < 1492): прямая, идущая вниз, уставка отрицательная до –164 °/с
- горизонтальная прямая (1492 ≤ X ≤ 1508): уставка = 0 (мёртвая зона)
- правый участок (X > 1508): прямая, идущая вверх, уставка положительная до +164 °/с

**4.2.b** Ширина мёртвой зоны: 1508 – 1492 = 16 мкс. Полный диапазон сигнала — 1000 мкс (от 1000 до 2000). В процентах: (16/1000)·100% = 1,6%.

**4.2.c** Максимальная уставка угловой скорости при крайнем правом положении стика (channel_1 = 2000 мкс): (2000 – 1508)/3 = 492/3 = 164 °/с. При отклонении влево –164 °/с.

**4.2.d** Мёртвая зона введена, чтобы дрон не реагировал на малые случайные отклонения сигнала. Реальные RC-передатчики имеют погрешность ±5…10 мкс. Без мёртвой зоны дрон получал бы ненулевую уставку даже при отпущенном стике, что привело бы к постоянному медленному вращению. Пилот был бы вынужден непрерывно корректировать. Мёртвая зона шириной 16 мкс полностью «гасит» сигнал вблизи центра.

### 2.3 Численный расчёт ПИД (задание 4.3)

Дано: Kp = 2,0; Ki = 0,04; Kd = 20,0; Imem[0] = 0; e[-1] = 0. Последовательность ошибок e[k]: 10, 8, 5, 2, 0, –1.

Использованы дискретные формулы:

$$P[k] = K_p \cdot e[k]$$

$$I_{mem}[k] = I_{mem}[k-1] + K_i \cdot e[k]$$

$$D[k] = K_d \cdot (e[k] - e[k-1])$$

$$u[k] = P[k] + I_{mem}[k] + D[k]$$

**Таблица 1 — Результаты численного расчёта ПИД-регулятора**

| k | e[k] | P[k] | I[k] | D[k] | u[k] |
|---|------|------|------|------|------|
| 0 | 10 | 20,0 | 0,4 | 200,0 | 220,4 |
| 1 | 8 | 16,0 | 0,72 | –40 | –23,28 |
| 2 | 5 | 10,0 | 0,92 | –60 | –49,08 |
| 3 | 2 | 4,0 | 1,00 | –60 | –55,0 |
| 4 | 0 | 0 | 1,00 | –40 | –39,0 |
| 5 | –1 | –2,0 | 0,96 | –20 | –21,04 |

**4.3.b** При переходе от k=0 к k=1 ошибка уменьшилась всего на 2 единицы (с 10 до 8), но выход регулятора упал с +220,4 до –23,28 — почти на 244 единицы. Причина — дифференциальная составляющая D[1] = –40. Она реагирует не на величину ошибки, а на скорость её изменения. Когда ошибка быстро уменьшается, регулятор «предчувствует» приближение к нулю и заранее снижает выход, чтобы избежать перерегулирования.

**4.3.c** D-составляющая «предсказывает» будущее поведение ошибки. Если ошибка быстро уменьшается, разность отрицательна, и D-составляющая становится отрицательной, снижая выход. Если ошибка начинает расти, D-составляющая становится положительной и увеличивает выход. Это демпфирует систему, гасит колебания и предотвращает перерегулирование.

**4.3.d** При постоянной ошибке e = 5 °/с, Ki = 0,04, за 100 итераций без Anti-Windup: Imem[100] = 0 + 0,04·5·100 = 20. Без ограничения интеграл продолжал бы расти линейно, что опасно — после устранения ошибки накопленный интеграл вызовет перерегулирование.

### 2.4 Anti-Windup (задание 4.4)

**4.4.a** Интегральное насыщение возникает, когда регулятор долго не может устранить ошибку. Например, дрон лежит на боку — ошибка по крену большая и постоянная, интеграл накапливается. Когда дрон отрывается от земли, ошибка уменьшается, но накопленный интеграл продолжает действовать, вызывая резкий завал в другую сторону (перерегулирование). Это явление называется windup.

**4.4.b** В файле PID.ino Anti-Windup реализован ограничением интеграла и выхода величиной ±400.
```cpp
pid_i_mem_roll_rate += pid_error_temp * pid_i_gain_roll;
if (pid_i_mem_roll_rate > 400) pid_i_mem_roll_rate = 400;
else if (pid_i_mem_roll_rate < -400) pid_i_mem_roll_rate = -400;

pid_output_roll = ... ;
if (pid_output_roll > 400) pid_output_roll = 400;
else if (pid_output_roll < -400) pid_output_roll = -400;

pid_i_mem_roll_rate += pid_error_temp * pid_i_gain_roll;
if (pid_i_mem_roll_rate > 400) pid_i_mem_roll_rate = 400;
else if (pid_i_mem_roll_rate < -400) pid_i_mem_roll_rate = -400;

pid_output_roll = ... ;
if (pid_output_roll > 400) pid_output_roll = 400;
else if (pid_output_roll < -400) pid_output_roll = -400;
```
**4.4.c** При e = 50 °/с, Ki = 0,04, Imax = 400. Без Anti-Windup интеграл растёт линейно: I = 2k. С Anti-Windup при k = 200 достигает 400 и останавливается. До 200 итераций линии совпадают, после 200 — расходятся.

**4.4.d** N = Imax / (Ki·e) = 400 / (0,04·50) = 200 итераций. При частоте 250 Гц (период 4 мс) это время: 200·0,004 = 0,8 с.

**4.5.a** В файле Flight_Controller.ino в функции loop():

- esc_2 = 1500 + (–30) – 50 – 20 = 1400

Все значения в диапазоне 1100…2000 мкс, ограничения не срабатывают.

**4.5.d** Нижняя граница 1100, а не 1000, потому что сигнал 1000 мкс означает полную остановку мотора. Если в полёте мотор остановится, дрон перевернётся. Минимальный рабочий сигнал 1100 мкс гарантирует, что моторы постоянно вращаются, сохраняя управляемость.

## 4 Предложения по улучшению

В текущей версии используется линейная компенсация батареи. Более точный алгоритм — квадратичная компенсация:

$$comp = (12.4 / voltage)^2$$

Это соответствует физической зависимости $F \sim U^2$. Сложность реализации низкая — достаточно заменить линейную добавку на умножение.
